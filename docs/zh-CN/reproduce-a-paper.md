# 复现一篇论文

> [English](../en/reproduce-a-paper.md) | [简体中文](reproduce-a-paper.md)

## 目标

当目标是独立检验论文报告的结果与核心结论是否成立时，运行 `/paper-reproduce`。复现要用新的实现与运行产物重建论文的证据链；只总结论文不算复现。

复现可以得到正面或负面结论。若某条必需命题只是因为工作停了而仍为 `unestablished`，任务就还没有完成。

## 建立论证骨架

只提取复现目标真正需要的命题。图可以很浅，也可以是多层 DAG：

```text
新产物 ──evidence──► 结果命题 ──evidence──► 核心命题
                           warrant                 warrant
```

所有节点都是 Proposition。当一个报告结果可能独立失败、需要自己的 qualifier 或 rebuttal、区分不同数据集或指标，或会被多个结论复用时，才把它单独建成命题。否则把新产物直接附到被它检验的命题上。

执行之前：

- 保留论文目标的原意；
- 为每层推理写出预期 warrant；
- 复现证据槽保持为空；
- 所有提取出的命题保持 `unestablished`。

论文规定“要复现什么”，但不能证明自己的结果为真。不要把论文、预计算输出、发布权重或补充结果文件当作直接受测命题的证明。

## 定义证据义务

对每条必须靠新运行确立的命题，预先写清：

- 目标量与范围；
- 方法、数据、指标、基线和容差；
- 成功运行必须产生的产物；
- 哪种结果构成支持、限制、否定或仍不确定；
- 复现成功所需的最低正向 qualifier。

阈值要在看到结果之前确定。每条需要新运行的 `unestablished` 叶命题，都是一项未完成义务。

## 从叶子向上执行

把边界清晰的实现与实验交给 `code-experimenter`；只有在保持同一全规模测试语义时，才用 `code-optimizer` 降低成本。便宜的 sanity check 可以验证实现行为，但只有预先定义的正式运行才能确立目标结果。

每完成一项义务：

1. 检查实现和产物；
2. 把代码、执行轨迹、原始输出、指标计算和简短证据报告附到被直接检验的命题；
3. 写明为什么这次运行能支撑该命题的 warrant；
4. 设置证据真正挣到的 qualifier；
5. 重新判断证据已变化的下游命题。

若下游 warrant 所必需的证据命题仍为 `unestablished`，不要先把下游命题判到正向档。

## 审计不一致与阻塞

意外结果不自动等于 rebuttal。接受图后果之前，把单个不一致或声明的阻塞交给 `discrepancy-auditor`。

- 实现、数据、环境或指标错误：修复并重跑；
- 测试不足：义务保持 `unestablished`；
- 可辩护的更窄结果：另建更窄命题，同时保留原范围缺口；
- 可信矛盾：建立有独立证据的命题，攻击受影响的 content 或 warrant；
- 仍不确定：留下精确的待补证据要求。

“缩小范围”意味着还要执行缩小后的任务，不是只报出这个分类就停止。

## 判断完成

先判断叶命题，再判断 rebuttal 与晋升后的 warrant，最后判断下游结论。报告完成前确认：

- 每条必需命题都有可辩护的 qualifier，或有经过审计的“当前无法执行任何可辩护测试”说明；
- 每条正向结论都得到其 warrant 所要求的证据命题支撑；
- 没有重要 rebuttal 留在未判断状态；
- 可能推翻结论的结构 warning 已清除或写明理由 dismiss；review finding 已在修正后由新 review 取代，或已写明理由 dismiss；
- `get_stats` 如实展示剩余红点。

`review` 是可选且显式的，只用于来源忠实性或推理有效性的第二意见；它不能代替主 Agent 的 qualifier 判断。

## 需要直接指出的跑偏

- **看到结果后改写目标。** 保留原命题，把不同结果记录为证据或 rebuttal。
- **用论文自己的产物证明论文。** 它们可定义目标或辅助调试，但不构成独立复现。
- **只报数字，没有审计链。** 附上实现、执行轨迹、原始结果、计算与报告。
- **warrant 只说“结果支撑结论”。** 写出让这类结果与这类结论发生关系的通用推理原则。
- **把 warning 当闸门或直接忽略。** warning 是非阻断信号；应检查、修复或写理由 dismiss。
